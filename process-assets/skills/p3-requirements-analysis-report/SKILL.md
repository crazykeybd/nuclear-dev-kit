# 软件需求分析报告（p3-requirements-analysis-report）
## 用途
生成中广核研究院《软件需求分析报告》。规定软件需求与规格，作为设计基础、编写代码/测试用例及测试的依据，也是开发方与用户确定功能的主要依据。

母版：过程资产库V5.0/03_软件需求分析/03-02.0【模板】中文软件名+英文软件名+空格+二位版本号+需求分析报告.docx

## 章节结构
摘要 → 缩略语表 → 主要符号表 → 中英文术语对照表 → 参考文献 → 1 前言（1.1 目的 / 1.2 综述）→ 2 软件（系统）概述（2.1 总体功能简介 / 2.2 约束、假设和依赖 / 2.3 运行环境要求）→ 3 软件功能需求（3.1 XXXX功能需求 / 3.2 XXXX功能需求；每项含：功能需求概述 / 输入输出要求（输入、输出）/ 特定要求）→ 4 非功能性需求（4.1 软件编程规范需求 / 4.2 软件运行性能需求 / 4.3 软件维护需求 / 4.4 外部接口需求：用户接口、硬件接口、软件接口）→ 5 需求矩阵表

## 表格字段
表 1 功能需求输入物理量说明表：物理量名称 | 量纲 | 有效范围 | 其他必要要求（如有）
需求矩阵表：序号 | 标识 | 需求项名称 | 需求分析报编号/章节 | 需求内容简述 | 需求标识 | 需求变更标识 | 优先级 | 预计工期 | 实现方式 | 阶段产品（版本号）
封面：项目名称、文件编码、外部编码、项目代码、子项号、文件类型、设计阶段、参考文件编码、REV.、文件种类（A:Identical / B:Modified / C:New）、部门内部编码、关键词
## 填写要点
需求用"软件应……"方式陈述，端到端表述避免与模块混淆。
运行环境/性能需求必须可测试、有量化指标并写入需求矩阵。
无特殊约束写"本软件无特殊要求"。
本模板需求标识取值为：新增 / 缺陷（修复缺陷项）/ 优化（增强功能性能）；优先级、实现方式同 03-01 模板。
## 生成方法
复制母版 DOCX 后用 python-docx 填充章节与表格；无母版时按上述结构新建。
