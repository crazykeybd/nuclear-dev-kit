# 软件测试报告（p6-test-report）
## 用途
生成软件《测试报告》，记录测试过程、结果与缺陷分析。命名规则：中文软件名+英文软件名+空格+二位版本号+测试报告。

母版：过程资产库V5.0/06_软件测试/06-02【模板】中文软件名+英文软件名+空格+二位版本号+测试报告.docx

## 章节结构
封面/版本记录 → 摘要+关键词 → 缩略语/符号/术语 → 参考文献（一般含需求分析报告和测试计划）→ 1 概述 → 2 依据文件（2.1 参考标准、2.2 参考标准/项目文件）→ 3 测试对象（3.1 软件概述[须说明对应代码版本号如 SVN/GIT]、3.2 测试环境、3.3 方法与工具、3.4 环境差异影响分析）→ 4 测试结果与缺陷分析（4.1 测试组织与人员、4.2 测试用例总结、4.3 测试记录[静态/单元/集成/系统]、4.4 覆盖分析[需求覆盖率、单元/代码覆盖率]、4.5 缺陷统计与跟踪、4.6 活动进度与偏差）→ 5 测试总结与评价 → 附录A 需求-用例对应表 / B 静态测试问题解释 / C 单元测试执行记录 / D 集成测试执行记录 / E 系统首轮执行记录 / F 系统回归执行记录 / G 缺陷跟踪表 / H 未修复缺陷记录表

表格字段（23 张，要点）
表3-1 测试环境 序号|配置|详细信息；表3-2 工具清单（静态 C++test / 单元 GTEST / 系统 LoadRunner）
表4 系列：用例总结 测试阶段|用例总数|执行总数|通过项|(阻塞项)|通过率%；静态缺陷记录 序号|缺陷/漏洞类型|严重度|数量；代码覆盖率 行覆盖率|函数覆盖率|判定覆盖率|条件覆盖率；缺陷统计 等级/状态|缺陷总数|关闭|撤销|暂缓；进度表 测试阶段|计划/实际开始/结束|备注；偏差表 序号|偏差名称|描述|偏差原因|影响分析|备注
附录A 需求-用例矩阵 编号|需求内容|各功能模块列√|测试用例数|测试用例编号
附录C 单元执行记录 用例编号|用例名称|单元名称|测试内容|测试输入数据|预期结果|实际结果|确认|执行时间（编号规则 软件简称_Unit_序号）
附录D 集成记录（含执行日期）；附录E/F 系统首轮/回归记录 用例编号|用例名称|测试内容|输入数据|测试步骤|测试类型|期望结果|实际结果|确认|执行日期
附录G 缺陷跟踪 序号|问题等级|问题简述|问题描述|缺陷状态|提交人|日期|处理人|原因分析/解决方案/拒绝原因|关闭日期|对应用例
附录H 未修复缺陷 序号|问题等级|问题描述|缺陷状态|处理人|未修复原因|拟修复版本
## 填写要点
须给出测试代码版本号（SVN/GIT）；含环境差异影响分析。
缺陷按五级分类；需求覆盖率=用例涵盖需求数/所有需求数。
未用工具时给单元覆盖率；用工具优先给代码覆盖率。
附录B 静态测试问题解释必须为签字版；各记录附 SVN 归档路径。
结论给出功能符合需求、缺陷闭环、具备应用基础的总结与评价。
## 生成方法
复制母版 DOCX 后用 python-docx 填充章节与 23 张表；无母版时按上述结构新建。
